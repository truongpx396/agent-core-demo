# Tasks: Billing Migrations and Idempotency Conflicts

**Input**: `specs/012-billing-migrate-idempotency/` (spec.md, plan.md, research.md, data-model.md, contracts/, quickstart.md)

**Prerequisites**: plan.md, spec.md. Constitution Principles I, II, IV are non-negotiable; the package still imports nothing from the application; the model still has no path to a balance.

**Organization**: one phase per user story group, and each is one PR. US1 = PR A (the migration tool). US2 and US3 = PR B (the idempotency conflict and the operator command's side of it); PR B starts only after PR A is merged, because it ships its column to existing databases through the tool.

**Task kinds**: `DOCS` documentation only · `NEW` a new file · `EDIT` a change to an existing file · `TEST` a test · `VERIFY` a check whose result is recorded, not code.

**Commands**: `source .venv/bin/activate` first. `export PATH=$PATH:/usr/local/bin:/opt/homebrew/bin` (Docker and `gh` are not on the Bash tool's PATH). Run package tests from `packages/billing` with `PYTHONPATH=$PWD/src`; `make` exports the path itself. The developer's compose stack may be running: never `make clean`, `clear-*`, `restart-all`. Never execute the `provider_sandbox` tier (it uses real keys) unless the user asks in that turn.

**Rules that apply to every task** (CLAUDE.md and the constitution): every `# noqa` and `# type: ignore[...]` carries a reason; a broad `except Exception` carries `# noqa: BLE001 - <reason>`; comments explain why; a fix lands with a regression test that fails without it; a verification is a *CI-shaped* run, not only a local one (PR #161's two failures were a subprocess that does not inherit `pytest`'s `pythonpath`, and a `0700` bind mount that macOS hides). Commit prefixes `fix:` `feat:` `test:` `docs:` `infra:` `chore:`; each body states the failure mode and the root cause; end with the attribution line from the session's system reminder.

## Phase 2: User Story 1 (P1), PR A. An operator brings any database up to date, safely, and can gate a deploy on it

**Goal**: `credit-billing-migrate` and `credit_billing.migrate` apply the shipped scripts in order, record them, report status without writing, gate a deploy, serialise concurrent runners, bound every wait, roll a failed script back whole, and adopt a host-initialised database.

**Independent Test**: against a throwaway Postgres, an empty database is brought up to date by one command and a second run changes nothing; a host-initialised database is adopted without touching a row; four simultaneous runs apply each script once; a locked table makes the run stop with status 4 within the wait; `--check` exits 1 exactly when a script is pending or changed.

**Independent Test**: grant 500 under K; again (duplicate); 600 (refused naming `amount`); a different reason (refused naming `reason`). Two events for one refund stay a duplicate; a webhook grant replayed with a later expiry stays a duplicate; a database created from the pre-change script gains the column through `credit-billing-migrate` and its old rows keep today's behaviour.
