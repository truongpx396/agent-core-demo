# Tasks: Model Serving Seams and an Evaluation Harness

**Input**: `specs/014-model-serving-eval-harness/` — `plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`
**Prerequisites**: read `.claude/rules/testing.md` and `.claude/rules/runtime-reliability.md`; the constitution is `.specify/memory/constitution.md`.

**Tests**: REQUESTED. The spec makes testing part of the requirements (FR-008, FR-012, FR-042, SC-003, SC-005..011), the repo requires a
regression test for every bug-shaped risk, and several research claims are *to verify*. Tests come **before** the code they cover in
each group, and a test that guards a bug must be shown failing without the fix (CLAUDE.md).

**Organization**: by user story, and inside a story by **PR** — the PR boundaries are the plan's *Delivery* table (CLAUDE.md:
≤ ~400 hand-written lines per PR, ~1,000 ceiling; data, lock and generated files do not count). Every PR leaves
`make lint typecheck test` green and changes no default behavior until PR 8.

**PR map for the tasks outside a story group** (so every task has a home): T001 → PR 4 (first test that imports `ml_service`); T002, T003, T004 → PR 2; T090–T094 → **PR 9**, a small closing-docs PR after PR 8 (`ENGINEERING_PATTERNS.md`, `CLAUDE.md`, gates, spec housekeeping).

**Analysis remediation.** The `/speckit-analyze` pass of 2026-10-17 found 3 high, 6 medium and 5 low issues; each is fixed in the task named in *Analysis remediation* at the end of this file (H = high, M = medium, L = low).

## Format: `- [ ] T### [P?] [US#?] Description with file path`

- **[P]** — different files, no dependency on an unfinished task in the same group.
- **[US1]/[US2]/[US3]** — the story (setup, foundational and polish carry none).
- **HUMAN / MANUAL / OPERATOR** — cannot be completed by editing code. The agent must stop and hand these over; it never ticks them.
  HUMAN = a person's judgment (review, accept). MANUAL = a run on the maintainer's machine with live services. OPERATOR = a run
  that needs a configured stronger model and a judge.

## Path conventions

Application `app/`, scripts `scripts/` (the harness is `scripts/model_eval/`), the auxiliary image `docker/ml-service/` (its package is
`docker/ml-service/ml_service/`), data `evals/`, tests `tests/` (new: `tests/scripts/model_eval/`, `tests/ml_service/`).

## Phase 3: User Story 1 — judge any candidate against a recorded baseline (Priority: P1) 🎯 MVP

**Goal**: one command per model kind produces a report that puts a candidate next to the recorded baseline, with confidence intervals,
verdicts, efficiency and trade-offs, proved by control candidates.
**Independent test**: `quickstart.md` §1 — baseline recorded; the baseline-as-candidate control says `no_difference`, the random control `worse`;
a re-run reproduces every quality number. **Delivers no runtime change.**
