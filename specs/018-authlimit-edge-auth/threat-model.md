# Threat model: authlimit (spec 018, FR-035)

Scope: the service, its keys and Redis state, the Caddy wiring, the API's identity handling, and the web UI's token. The boundary of trust: the internet side of Caddy is hostile; the compose network between Caddy, the service, the API and Redis is trusted (until mTLS, which is not built). Cloudflare and per-address limits are out of scope (spec Decision 4).

| # | Threat | Defence | Test | Residual risk |
|---|---|---|---|---|
| T1 | A client sets `X-Tenant-Id`, `X-Principal-Id` or `X-Internal-Identity` itself | Identity mode ignores the first two; `copy_headers` deletes the third before setting it (measured R1); the API accepts only a validly signed identity | spoof variants in the smoke; API test with forged headers | Header mode (explicit opt-in) trusts headers: loud log, metric, alert |
| T2 | Algorithm confusion (`alg: none`, HS256 signed with the public key) | The allowed algorithm comes from the service, never from the token | shared vectors | none known |
| T3 | Key confusion: an internal identity used as an external token or the reverse | Different issuer, audience, `typ`, algorithm and key set, each pinned by each verifier | shared vectors both ways | none known |
| T4 | A token for another service or resource replayed here | Audience must contain the API's identifier; Casdoor does not validate `resource`, so scope is checked too | vectors: other audience, client id as audience, missing scope | A user can request any audience for themself; the tenant claim and scope are the boundary |
| T5 | Replay of an internal identity | 30 s lifetime (120 s maximum), unique `jti`, audience `agent-core-api`; reachable only inside the network | clock tests | A captured identity is usable for its lifetime inside the network. No `jti` store (named, not built) |
| T6 | Compromise of the internal signing key | Private key only in the service's mounted directory (mode 700), never in an image, log or Redis; consumers hold public keys; rotation with overlap; a replica refuses to start without it | key tests; secret scan of logs | Anyone who can read the directory can mint identities for any tenant. Managed secret store is the production step |
| T7 | A rogue key set served to the API (network position) | The key URL is fixed configuration on the compose network, not routed by Caddy | config test; Caddyfile test | The network is the boundary; a host or container compromise defeats it. mTLS or pinning named, not built |
| T8 | Compromise or withdrawal of Casdoor's signing key | Keys refreshed on an unknown `kid`; stale keys trusted at most 6 h, then fail closed; operator can restart replicas to drop the cache | grace tests | During an outage a withdrawn key is trusted up to the grace |
| T9 | Stolen or abandoned long-lived token (7-day default) | Revocation by person within 5 s on every replica; lifetime cap; recommendation to shorten and refresh | revocation smoke | Between theft and the operator noticing the token works. Revocation is manual |
| T10 | Flood of invalid tokens to exhaust the service or force key fetches | Each invalid token costs one verification (about 55 µs measured for RS256) and no Redis call; key refresh limited to once per 30 s per replica | refresh limiter test | Unauthenticated floods are not limited until the per-address layer exists (disclosed) |
| T11 | One tenant starves others | Per-tenant and per-person buckets keyed only on verified claims; shared across replicas | smoke: two tenants | Defaults are guesses until tuned from observation mode |
| T12 | Limiter keyed on an unverified claim | The key is built only after verification (mutation list) | mutation test | none known |
| T13 | Redis down | Limiter fails open (counted, alerted); revocation copy enforced up to 30 s then refuses (policy `closed`) | store-failure tests | A short Redis outage can briefly remove rate limits |
| T14 | Casdoor or Redis outage used to lock people out | Bounded grace; readiness removes only replicas that truly cannot check; liveness independent | outage smoke | After the grace everything is refused by design |
| T15 | Token or key in logs, metrics, errors | Logs carry route class, outcome, reason and ids only; labels never carry tenant, principal or token; error messages are fixed text | post-run log scan (SC-009) | A future change could add a field; the scan is part of the smoke |
| T16 | The external token reaches the API (and its logs) | `request_header -Authorization` after the check (measured) | smoke: upstream echo shows no `Authorization` | none known |
| T17 | Key-fetch address points somewhere hostile (configuration) | Operator-set only; `https` unless loopback or dotless in-network; the response is parsed strictly and sized | config tests | A hostile operator is out of scope |
| T18 | Script injection on the web page reads the token in `sessionStorage` | The page serves no third-party script; tokens are never put in URLs; short tab-scoped storage | UI check for storage and header use | XSS would expose the token. A server-side session cookie would avoid it (not built) |
| T19 | Authorization-code interception, redirect abuse | PKCE with a public client and an exact registered redirect URI (Casdoor compares exactly) | sign-in in the smoke | none known beyond Casdoor's own correctness (hardening unchecked, spec 017) |
| T20 | The route table drifts from the API, leaving a route unchecked or unlisted | Unlisted routes are verified and limited like a turn; a test walks the API's routes | drift test (PR 2) | A route listed `public` by mistake is unchecked; reviewed in the table |
| T21 | Time skew across replicas | Redis `TIME` for buckets; a bounded leeway for tokens; all replicas share one host | clock tests | Hosts with unsynchronised clocks need NTP |
| T22 | Supply chain: Go modules, base images | Pinned digests, `go.sum`, trivy and checkov on the new files, a small dependency list | CI | Transitive vulnerabilities appear over time |

Review checklist for the code (used in PR 1's description): every verification path returns a reason instead of panicking; no `recover` that hides a bug; no use of the token's own header to choose an algorithm; no log call that takes a header or claim value; every outbound call has a deadline.
